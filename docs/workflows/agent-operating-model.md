# Agent Operating Model

Status: accepted workflow reference

## First-Read And Context Rules

Start with repo-root `AGENTS.md`, then open only the narrow workflow, current-
state, source, test, or explicitly named local roadmap section required. Use
`rg`, file inventories, indexes, and heading scans before broad reads. Keep raw
logs and protected/local evidence behind concise pointers.

Keep changing context to objective; role/authority; stable program/cycle/wave
IDs; repo/candidate identity; freeze and ownership; latest evidence;
cumulative controls; unresolved gates; and one next safe action.

## Replace-Only Context Capsule

For work spanning turns, agents, or compaction, use one replace-only 300-500
word capsule containing objective/role/authority/IDs; repo/branch/worktree/base/
candidate/target/ownership; freeze and canonical sources; toolchain and latest
evidence; cumulative initial/repair/environment/time controls; unresolved
decision/safety/evidence/authority gates; and one next safe action. Replace it
wholesale on material change. Never append prior capsules or broad history.

## Program And Cycle Preflight

Documentation-only work uses its scoped route. At each candidate-producing
program or cycle boundary:

1. inspect complete status/worktree porcelain;
2. establish stable IDs and inherit cumulative controls;
3. classify role, authority, integration target, capacity, and safety gates;
4. prove toolchain, locks, configuration, fixtures/data shape, and relevant inputs;
5. run the cycle's one Scout pass and approve its brief as the Initial or Repair Requirements Freeze; and
6. establish one immutable wave ID, lane plan, and Role Lock.

## Requirements Freeze And Ledger

The freeze owns requirements/acceptance; decisions/deferrals; dependencies;
ownership; authority; toolchain/environment/fixture identity; L1-L4 matrix;
non-goals; technical-decision latitude; and change-control rules. A genuine
requirement or acceptance change closes the cycle and requires a new Scout
brief and freeze.

Maintain one replace-only ledger under the stable Program ID with gate state,
candidate/input identity, latest evidence, achieved delta, initial/repair/
environment-rerun counts, cycle results, operator-set limits, dependency-skips,
and next owner/action. Default to one initial plus two repair candidates.

## Planning And Close-Out

Roadmap phases do not replace lifecycle identity and local roadmaps never prove
shipped state. Plan one assembled candidate, not independent micro-
verifications. Verification occurs once per candidate with impact-based depth.
Close-out distinguishes documentation review from implementation evidence and
reports exact identity, scope, checks, failures, controls, side-effect
boundaries, publication state, and retained lanes.
