# Worker Delegation

Status: accepted workflow reference

## Unit And Capacity

Delegate concrete bounded work advancing the authorized objective: discovery
before requirements approval, implementation within the current freeze, or a
scoped documentation/audit task. The
[operating model](agent-operating-model.md) owns cycle, review and evidence
rules. Capacity batches inherit the same IDs and controls, not new allowances.

Use delegation where it adds independent acceptance, distinct expertise or
useful parallel work. Do not create a separate worker or handoff merely to fill
each role. The operating model's compact local-tooling route may keep discovery,
implementation and assembly with one owner and use one independent reviewer.

Use one active worktree and one writer by default. Additional writer worktrees
require explicit operator authorization for the named task and a retirement
plan. Read-only roles may use the same checkout without ownership or independence
conflicts; delegate review without manufacturing another worktree.

## Assignment Contract

Default to `fork_turns="none"` and the current replace-only capsule. Name stable
IDs, role, authority, exact owned files/modules, freeze excerpts/headings,
repo/worktree/base/target, dependencies, relevant inputs, protected-data and
non-goal boundaries, L1 checks, optional L2 uncertainty, evidence form,
handoff fields, and stop conditions. Point to unchanged freeze/input artifacts
instead of copying full history or recursively expanding pin chains. Use the
same current capsule/ledger epoch; do not create a shadow status layer.
Workers do not commit, push, integrate,
publish, deploy, or write live data unless explicitly assigned matching
authority.

Every assignment or resumption selects its current governance reference under
[Instruction Delivery And Reuse](worktrees.md#instruction-delivery-and-reuse).
Confirm the worker read the affected instructions; distinguish them from any
frozen artifact's historical authority. Do not assume a worktree shares main's
uncommitted instructions or that a previous task's context refreshed itself.

## Assembly And Repair

The Orchestrator assembles L1-qualified results in the owned candidate lane
and freezes one exact artifact. Give the independent Verifier that identity,
current delta/impact map and direct prior-review references. The Verifier owns
fresh/reused coverage and the whole-release boundary under
[Independent Review And Reuse](agent-operating-model.md#independent-review-and-reuse).
The author cannot select its own acceptance scope. Resolve critical execution
assumptions under the operating model before assembly; other L2/Verifier
diagnostics are optional for concrete questions. L4 requires separate authority.
Protected integration is not an automatic assembly step.

Use the role handoff for acceptance with no unresolved blocker and residual
uncertainty, or one complete Frozen Failure Inventory with root-cause clusters
and dependency-skips. Preserve exact triggers, impact and affected scope;
do not copy all previous inventories into the current handoff.

No repair occurs inside a rejected frozen candidate. When budget permits,
product repairs use the next cycle's Scout brief and approved freeze; compact
tooling successors may record that scope inline under the same cumulative
controls. Pre-assembly feedback remains inside the mutable wave. Repeated
contract-family failures require the operating model's concrete design
disposition before more implementation.

## Reclaiming A Lane

A timeout is unknown state, not failure. Request stop/report, wait when
practical, inspect status/diff and ownership, preserve useful partial work, and
reclaim only after confirming the writer is inactive and no unreviewed unique
work, protected data, or conflicting side effect remains.
